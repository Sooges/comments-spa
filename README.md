# Comments SPA

SPA-приложение «Комментарии»: пользователи оставляют комментарии и отвечают друг другу, ответы отображаются каскадом (на каждый комментарий можно ответить сколько угодно раз). К комментарию можно приложить картинку или текстовый файл, новые комментарии появляются у всех открытых страниц без перезагрузки.

**Стек:** ASP.NET Core Web API (.NET 10), Entity Framework Core, MS SQL Server, Angular 22, SignalR (WebSocket), nginx, Docker.

## Функции

- Форма комментария: `User Name` (латиница и цифры), `E-mail`, `Home page` (необязательно), `Text`, CAPTCHA, файл (необязательно). Проверка на клиенте и на сервере.
- Разрешённые HTML-теги в тексте: `<a href="" title="">`, `<code>`, `<i>`, `<strong>`; проверка закрытия тегов (валидный XHTML), панель кнопок `[i]`, `[strong]`, `[code]`, `[a]`, предпросмотр без перезагрузки страницы.
- Защита от XSS и SQL-инъекций.
- Заглавные комментарии выводятся таблицей с сортировкой по `User Name`, `E-mail` и дате (в обе стороны), по умолчанию новые сверху; по 25 комментариев на странице.
- Ответы на комментарии (сколько угодно на каждый, вложенность до 100 уровней), каскадное отображение.
- Картинки JPG, GIF, PNG (больше 320×240 пропорционально уменьшаются) и текстовые файлы TXT до 100 КБ; просмотр в окне lightbox с визуальными эффектами.
- Данные о клиенте (IP-адрес, User-Agent) сохраняются вместе с комментарием.
- **Queue, Cache, Events, WebSocket:** очередь уведомлений, кэш страниц списка, события, SignalR (см. раздел ниже).

## Быстрый запуск (Docker)

Нужен только Docker: Docker Desktop (Windows, macOS) или Docker Engine с Compose (Linux).

1. Скачать репозиторий:

   ```bash
   git clone https://github.com/Sooges/comments-spa.git
   cd comments-spa
   ```

2. Создать файл настроек:

   ```bash
   cp .env.example .env
   ```

3. Собрать и запустить всё приложение (первая сборка занимает несколько минут):

   ```bash
   docker compose up -d --build
   ```

4. Открыть в браузере `http://localhost:8080`.

Остановить приложение с сохранением данных:

```bash
docker compose down
```

Остановить и удалить данные (базу и загруженные файлы):

```bash
docker compose down -v
```

Приложение состоит из трёх контейнеров:

| Контейнер | Что делает |
|---|---|
| `comments-db` | MS SQL Server 2022 (редакция Express), данные в томе `mssql-data` |
| `comments-api` | ASP.NET Core API, при старте применяет миграции, загруженные файлы лежат в томе `uploads` |
| `comments-web` | nginx: отдаёт Angular-приложение и передаёт запросы `/api` и `/hubs` (WebSocket) на API |

## Настройки

Настройки лежат в файле `.env` (пример: `.env.example`).

| Переменная | Описание | По умолчанию |
|---|---|---|
| `MSSQL_SA_PASSWORD` | пароль SQL Server (минимум 8 символов, заглавные и строчные буквы, цифры и символы; не используйте `;`) | пароль для разработки из `.env.example` |
| `WEB_PORT` | порт сайта на компьютере или сервере | `8080` |

> Пароль в `.env.example` предназначен только для локальной разработки. На сервере его нужно заменить.

## Развёртывание на сервере (VDS)

Нужен сервер с Linux, 2 ГБ памяти минимум (для SQL Server), лучше 4 ГБ.

1. Установить Docker по [инструкции](https://docs.docker.com/engine/install/) для вашей системы.
2. Скачать репозиторий и создать файл настроек (команды из раздела «Быстрый запуск»).
3. В файле `.env` задать свой пароль `MSSQL_SA_PASSWORD` и `WEB_PORT=80`.
4. Запустить:

   ```bash
   docker compose up -d --build
   ```

5. Убедиться, что порт 80 открыт в файерволе сервера, и открыть `http://<адрес сервера>`.

Полезные команды: `docker compose ps` (состояние), `docker compose logs -f api` (логи API), `git pull` и `docker compose up -d --build` (обновление).

База данных наружу не открывается: порт `1433` опубликован только на `127.0.0.1` самого сервера. Контейнеру API разрешено не больше 1 ГБ памяти (`mem_limit` в `docker-compose.yml`), чтобы один тяжёлый запрос не забрал всю память сервера.

**HTTPS.** Поставьте перед приложением обратный прокси (например, Caddy на этом же сервере), в `.env` укажите `WEB_PORT=8080`, а прокси направьте на `127.0.0.1:8080`. Реальный адрес посетителя берётся из заголовка `X-Forwarded-For`, который прокси добавляет сам (nginx в контейнере доверяет ему только из частных сетей Docker).

**Обновление.** После `git pull` команда `docker compose up -d --build` пересоздаёт изменившиеся контейнеры. Сайт при этом не нужно перезапускать вручную: nginx сам находит новый адрес API. Страница `index.html` не кэшируется браузером, поэтому после обновления посетители сразу получают новую версию.

**Mac с чипом Apple (M1 и новее).** Образ SQL Server собран только под архитектуру x86, и такой Mac запускает его через эмуляцию Docker Desktop (может не заработать). Надёжнее запускать проект на Linux или Windows.

## Интерфейс

- **Форма комментария** (`User Name`, `E-mail`, `Home page`, `Text`, файл, CAPTCHA). Поля проверяются на клиенте теми же правилами, что и на сервере, ошибки сервера показываются у соответствующих полей.
- **Панель тегов** `[i]`, `[strong]`, `[code]`, `[a]`: оборачивает выделенный текст в тег (для ссылки спрашивает адрес).
- **Предпросмотр** без перезагрузки страницы: текст отправляется на сервер, который возвращает тот HTML, что будет сохранён. Пока предпросмотр открыт, он обновляется при наборе текста.
- **Список**: заглавные комментарии выводятся таблицей, по умолчанию новые сверху. Сортировка по `User Name`, `E-mail` и дате в обе стороны (клик по заголовку столбца), по 25 комментариев на странице.
- **Ответы** отображаются каскадом, вложенность до 100 уровней (первые 6 уровней сдвигаются вправо, более глубокие остаются на одной линии, чтобы цепочка не уезжала за экран); у ответа показывается цитата комментария, на который он написан. Форма ответа открывается кнопкой «Ответить».
- **Файлы**: картинка открывается в окне lightbox (затемнение, анимация, закрытие по клику и по `Esc`), текстовый файл показывается в таком же окне.

## API

### `GET /api/comments`

Страница заглавных комментариев (те, что не являются ответами) вместе со всеми ответами в виде дерева.

| Параметр | Значения | По умолчанию |
|---|---|---|
| `sortBy` | `date`, `userName`, `email` | `date` |
| `sortOrder` | `asc`, `desc` | `desc` (сначала новые, LIFO) |
| `page` | номер страницы, от 1 | `1` |

На странице 25 комментариев. Ответ содержит `items`, `page`, `pageSize`, `totalCount`, `totalPages`; у каждого комментария есть вложенный массив `replies`. Неверные значения параметров дают ответ `400`.

### `GET /api/captcha`

Возвращает новую CAPTCHA: `id` и картинку `image` (PNG в виде data URI). Код состоит из латинских букв и цифр, хранится на сервере 5 минут и может быть проверен только один раз (даже при неверном вводе нужно запросить новую картинку).

### `POST /api/comments`

Создаёт комментарий. Данные отправляются формой (`multipart/form-data`), потому что к комментарию можно приложить файл. Чтобы ответить на комментарий, нужно передать его `id` в поле `parentId`. Пример полей:

```
userName=john
email=john@example.com
homePage=https://example.com
text=Hello <strong>world</strong>
parentId=1                    (необязательное)
captchaId=<id из /api/captcha>
captchaCode=<код с картинки>
file=<картинка или TXT>       (необязательное)
```

Правила:

| Поле | Правило |
|---|---|
| `userName` | обязательное, только латинские буквы и цифры, до 50 символов |
| `email` | обязательное, корректный e-mail |
| `homePage` | необязательное, адрес `http://` или `https://` |
| `text` | обязательное, до 5000 символов, разрешены только теги `<a href="" title="">`, `<code>`, `<i>`, `<strong>` |
| `captchaId`, `captchaCode` | обязательные, код регистр не учитывает |
| `parentId` | если указан, такой комментарий должен существовать |
| `file` | необязательное, одна картинка (JPG, GIF, PNG) или текстовый файл (TXT до 100 КБ), см. ниже |

При нарушении правил возвращается `400` с описанием ошибок на русском. Вместе с комментарием сохраняются IP-адрес и User-Agent клиента (за nginx берётся реальный адрес из заголовка `X-Forwarded-For`).

Поле `text` в ответе содержит уже **безопасный HTML**, его можно выводить на странице как есть.

### `POST /api/comments/preview`

Проверяет текст и возвращает `{ "html": "..." }`: так он будет выглядеть в комментарии. Ничего не сохраняется, CAPTCHA не нужна.

### `GET /api/attachments/{id}`

Отдаёт файл, приложенный к комментарию. У комментария в поле `attachment` есть `id`, `kind` (`image` или `text`), `fileName`, `size` и для картинок `width` и `height`.

## Файлы

- **Картинки** JPG, GIF, PNG. Формат определяется по содержимому файла, а не по расширению (файл `virus.png`, внутри которого текст, будет отклонён). Если картинка больше 320×240, она пропорционально уменьшается до этих размеров. Поворот фото, записанный камерой (метка EXIF), применяется, поэтому снимки с телефона не оказываются «на боку». JPEG остаётся JPEG, PNG остаётся PNG. Большой GIF сохраняется как PNG (анимация теряется), маленький GIF сохраняется без изменений.
- **Текстовые файлы** только `.txt`, не больше 100 КБ, в кодировке UTF-8 и без бинарных данных.
- Файлы лежат на диске в папке `uploads` (путь меняется настройкой `Storage:UploadsPath`) под именем, которое генерирует сервер. Имя, под которым файл загрузил пользователь, хранится только в БД для показа.
- Дополнительные ограничения, чтобы защитить сервер: картинка не больше 5 МБ и 25 млн пикселей.
- При отдаче файла сервер добавляет заголовки `X-Content-Type-Options: nosniff` и `Content-Security-Policy: default-src 'none'; sandbox`, поэтому содержимое файла не может выполниться в браузере.

## Очередь, кэш, события и WebSocket

```
сервис сохраняет комментарий в БД
        ↓
срабатывает событие CommentCreated (C# event)
        ↓                                   ↓
кэш списка сбрасывается сразу        уведомление кладётся в очередь
                                            ↓
                                     фоновый сервис достаёт его из очереди
                                            ↓
                                     SignalR отправляет «CommentAdded» всем браузерам
                                            ↓
                                     список на открытых страницах обновляется сам
```

- **События** (`Events/`). После сохранения `CommentService` вызывает `ICommentEvents.RaiseCommentCreated`. Если подписчик упадёт, комментарий уже сохранён и запрос не сломается, ошибка пишется в лог.
- **Кэш** (`Services/CommentCache`). Страницы списка (по сочетанию сортировки и номера страницы) хранятся в `IMemoryCache` до 5 минут. При новом комментарии весь кэш сбрасывается: в ключ входит номер версии, он увеличивается, и старые страницы больше не находятся. Номер берётся до загрузки страницы, поэтому устаревшая страница не может занять место свежей. Если менять БД в обход приложения, кэш об этом не узнает и обновится не позже чем через 5 минут.
- **Очередь** (`Queue/`). Это `Channel<T>` в памяти приложения. Сохранение комментария в очередь **не** кладётся: комментарий пишется в БД прямо во время запроса, чтобы пользователь сразу видел результат или ошибку и ничего не терялось при перезапуске. В очередь попадает только уведомление для остальных пользователей.
- **Фоновый сервис** (`Workers/NotificationWorker`) читает очередь и отправляет сообщение через `IHubContext`. Ошибка одного сообщения не останавливает сервис.
- **WebSocket** (SignalR). Хаб доступен на `/hubs/comments`. Angular подключается через `@microsoft/signalr`, а когда приходит `CommentAdded`, список загружается заново (с задержкой 300 мс, если сообщения идут подряд). После обрыва связи список тоже перезагружается.

## Защита от XSS

Текст комментария не сохраняется «как есть». Перед записью в БД его разбирает `HtmlTextProcessor`:

- разрешены только теги `a`, `code`, `i`, `strong`; любой другой тег, атрибут (`onclick`, `style` и т. д.) или символ `<` вне тега отклоняются с ошибкой;
- теги должны быть закрыты и вложены правильно (как в XHTML): `<strong><i>x</strong></i>` не проходит, ссылку в ссылке вставить нельзя;
- у ссылки допустимы только `href` (абсолютный `http://` или `https://`, поэтому `javascript:` и `data:` невозможны) и `title`; к ссылке добавляются `rel="nofollow noopener noreferrer"` и `target="_blank"`;
- весь остальной текст экранируется (`&`, `<`, `>`, кавычки), поэтому в БД попадает только заранее известный набор тегов.

### `Comments`

| Поле | Тип | Описание |
|---|---|---|
| `Id` | int, PK | идентификатор |
| `ParentId` | int, FK на `Comments.Id`, null | родительский комментарий; null у заглавных |
| `UserName` | nvarchar(50) | имя пользователя |
| `Email` | nvarchar(254) | e-mail |
| `HomePage` | nvarchar(2048), null | сайт пользователя |
| `Text` | nvarchar(max) | текст комментария (не более 5000 символов) |
| `CreatedAt` | datetime2 | дата добавления (UTC; API отдаёт её с `Z`, а браузер показывает в местном времени) |
| `IpAddress` | nvarchar(45) | IP-адрес клиента |
| `UserAgent` | nvarchar(512) | браузер клиента |

Индексы: `ParentId`, `CreatedAt`, `UserName`, `Email`: по ним выбираются и сортируются заглавные комментарии.

### `Attachments`

У комментария не больше одного вложения (связь один к одному), при удалении комментария вложение удаляется вместе с ним.

| Поле | Тип | Описание |
|---|---|---|
| `Id` | int, PK | идентификатор |
| `CommentId` | int, FK на `Comments.Id`, уникальный | комментарий, к которому приложен файл |
| `Kind` | nvarchar(20) | `Image` или `Text` |
| `FileName` | nvarchar(255) | имя файла, которое загрузил пользователь |
| `StoredFileName` | nvarchar(100) | имя файла на диске |
| `ContentType` | nvarchar(100) | тип содержимого |
| `Size` | bigint | размер сохранённого файла в байтах |
| `Width`, `Height` | int, null | размеры картинки |

## Принятые решения

- **Одна таблица с самосвязью.** Комментарий и ответ хранятся одинаково, вложенность ограничена 100 уровнями (всё дерево отправляется в браузер одним JSON, слишком глубокое дерево записать нельзя). Удалить комментарий, у которого есть ответы, нельзя (`ON DELETE NO ACTION`).
- **Отдельные DTO.** API не отдаёт клиенту IP и User-Agent и не принимает служебные поля вроде даты создания.
- **Сортировка только по разрешённым полям.** Поле и направление задаются перечислениями (`enum`), произвольное значение не попадает в запрос. Запросы к БД выполняются через EF Core с параметрами, поэтому защита от SQL-инъекций обеспечена.
- **Стабильная пагинация.** Вторым ключом сортировки всегда идёт `Id`, чтобы комментарии не дублировались и не пропадали при переходе между страницами.
- **CAPTCHA хранится на сервере.** Код никогда не отдаётся клиенту, наружу уходит только картинка. Картинка рисуется библиотекой SkiaSharp (лицензия MIT), код хранится в `IMemoryCache` 5 минут и сгорает после первой проверки (проверка и удаление кода выполняются неделимо, поэтому даже при множестве одновременных запросов один код сработает только один раз). CAPTCHA проверяется до разбора приложенного файла, чтобы запросы без верного кода не нагружали сервер обработкой картинок. В Docker-образ API установлен шрифт DejaVu для этой картинки.
- **Дерево ответов загружается по уровням.** На каждый уровень вложенности один запрос, дерево собирается в памяти. Это проще рекурсивного SQL и достаточно для задачи.
- **Один адрес для сайта и API.** nginx отдаёт страницу и передаёт `/api` и `/hubs` на API, поэтому браузеру не нужны настройки CORS.
