# Comments SPA

SPA-приложение «Комментарии»: пользователи оставляют комментарии и отвечают друг другу, ответы отображаются каскадом (на каждый комментарий можно ответить сколько угодно раз).

**Стек:** ASP.NET Core Web API (.NET 10), Entity Framework Core, MS SQL Server, Angular, SignalR, Docker.

## Статус

Проект разрабатывается по этапам, каждый этап в отдельной ветке `feature/...`.

- [x] Каркас Web API, модель данных, миграция, MS SQL в Docker
- [x] API комментариев: создание, ответы, список с сортировкой и пагинацией
- [ ] Валидация, фильтр HTML-тегов, защита от XSS, CAPTCHA
- [ ] Загрузка картинок и текстовых файлов
- [ ] Интерфейс на Angular
- [ ] Очередь, кэш, события, WebSocket (SignalR)
- [ ] Docker-образ всего приложения, схема БД

## Запуск для разработки

Нужны: .NET 10 SDK и Docker.

1. Создать файл окружения:

   ```bash
   cp .env.example .env
   ```

2. Поднять базу данных:

   ```bash
   docker compose up -d db
   ```

3. Запустить API (при старте применяются миграции, база `CommentsDb` создаётся автоматически):

   ```bash
   dotnet run --project backend/CommentsApi
   ```

API будет доступен на `http://localhost:5154`. Примеры запросов лежат в `backend/CommentsApi/CommentsApi.http`.

> Пароль в `.env.example` предназначен только для локальной разработки. Для сервера его нужно заменить.

## API

### `GET /api/comments`

Страница заглавных комментариев (те, что не являются ответами) вместе со всеми ответами в виде дерева.

| Параметр | Значения | По умолчанию |
|---|---|---|
| `sortBy` | `date`, `userName`, `email` | `date` |
| `sortOrder` | `asc`, `desc` | `desc` (сначала новые, LIFO) |
| `page` | номер страницы, от 1 | `1` |

На странице 25 комментариев. Ответ содержит `items`, `page`, `pageSize`, `totalCount`, `totalPages`; у каждого комментария есть вложенный массив `replies`. Неверные значения параметров дают ответ `400`.

### `POST /api/comments`

Создаёт комментарий. Чтобы ответить на комментарий, нужно передать его `id` в поле `parentId`.

```json
{
  "userName": "john",
  "email": "john@example.com",
  "homePage": "https://example.com",
  "text": "Hello",
  "parentId": null
}
```

Правила: `userName`, `email`, `text` обязательны; `email` должен быть корректным адресом; `homePage`, если указан, должен быть URL; если указан `parentId`, такой комментарий должен существовать. При нарушении правил возвращается `400`. Вместе с комментарием сохраняются IP-адрес и User-Agent клиента.

## База данных

Одна таблица `Comments`:

| Поле | Тип | Описание |
|---|---|---|
| `Id` | int, PK | идентификатор |
| `ParentId` | int, FK на `Comments.Id`, null | родительский комментарий; null у заглавных |
| `UserName` | nvarchar(50) | имя пользователя |
| `Email` | nvarchar(254) | e-mail |
| `HomePage` | nvarchar(2048), null | сайт пользователя |
| `Text` | nvarchar(max) | текст комментария (не более 5000 символов) |
| `CreatedAt` | datetime2 | дата добавления (UTC) |
| `IpAddress` | nvarchar(45) | IP-адрес клиента |
| `UserAgent` | nvarchar(512) | браузер клиента |

Индексы: `ParentId`, `CreatedAt`, `UserName`, `Email`: по ним выбираются и сортируются заглавные комментарии.

## Принятые решения

- **Одна таблица с самосвязью.** Комментарий и ответ хранятся одинаково, глубина вложенности не ограничена. Удалить комментарий, у которого есть ответы, нельзя (`ON DELETE NO ACTION`).
- **Отдельные DTO.** API не отдаёт клиенту IP и User-Agent и не принимает служебные поля вроде даты создания.
- **Сортировка только по разрешённым полям.** Поле и направление задаются перечислениями (`enum`), произвольное значение не попадает в запрос. Запросы к БД выполняются через EF Core с параметрами, поэтому защита от SQL-инъекций обеспечена.
- **Стабильная пагинация.** Вторым ключом сортировки всегда идёт `Id`, чтобы комментарии не дублировались и не пропадали при переходе между страницами.
- **Дерево ответов загружается по уровням.** На каждый уровень вложенности один запрос, дерево собирается в памяти. Это проще рекурсивного SQL и достаточно для задачи.
